# Recuperar según la capa del bloqueo

| Síntoma / registro | Comprobar primero | Siguiente paso y comprobación |
| --- | --- | --- |
| No aparece el iPhone físico, device unavailable | Si el cable admite datos, si el teléfono está desbloqueado y ha confiado, y si Xcode terminó el emparejamiento | Vuelve a conectar y ejecuta discover. Confirma que lo devuelto es el iPhone físico de destino y evita usar por error el simulador u otro dispositivo. |
| Xcode aún no completó el primer arranque, la licencia o faltan componentes | El developer directory que devuelve doctor, la versión de Xcode y el estado del primer arranque | El usuario instala un Xcode completo y completa los avisos del sistema; después, doctor. Instalar solo Command Line Tools no basta para compilar PUA. |
| Versión de iOS / developer disk image incompatibles | El iOS actual, el Xcode elegido y el error de preparación del dispositivo | Actualiza o elige un Xcode compatible según esa información y completa la preparación del dispositivo. No reintentes sin límite el mismo binario. |
| Developer Mode disabled | El interruptor de modo de desarrollador en el teléfono y la confirmación tras reiniciar | El usuario termina de activarlo y reinicia; discover vuelve a reconocer el dispositivo y después start. Que el dispositivo se viera antes de reiniciar no significa que el estado nuevo esté preparado. |
| signing requires development team / no signing identity | Apple Account, Team y certificado de desarrollo en Xcode | El usuario inicia sesión en Xcode y elige su propio Team; después configure/build. No pongas la contraseña de la cuenta en un archivo de configuración. |
| bundle identifier cannot be registered / no profiles | El bundle ID del target Runner y el provisioning del equipo | Vuelve a hacer configure con un bundle ID que el equipo del usuario pueda firmar. Ten en cuenta el sufijo `.xctrunner` del XCTest Runner y verifica con otra compilación. |
| maximum number of apps for free development profiles | Si el Personal Team ya tiene 3 apps de desarrollo | Explica el límite que señala el sistema. El usuario decide si desinstala una app de desarrollo que no necesite o si usa otro equipo válido que ya tenga. No borres apps por tu cuenta ni obligues a comprar un programa de desarrollador. |
| profile / certificate expired, el Runner antiguo ya no arranca | La validez de la firma en el registro de compilación y el vencimiento del profile | Vuelve a hacer build/start con la configuración local existente y comprueba READY de nuevo. Un profile gratuito suele necesitar volver a firmarse a los 7 días; lo concreto lo marca el profile actual. No te limites a reabrir el puerto. |
| developer not trusted / unable to verify | La entrada de desarrollador en el teléfono, la red y el aviso de Xcode | El usuario completa la confianza o la verificación en la entrada de desarrollador actual y revisa la red según el error del sistema. No revoques certificados compartidos de otros proyectos. |
| build succeeded, pero HTTP no es alcanzable | Si la prueba del Runner sigue en marcha, el proceso de reenvío USB y el puerto local | Confirma por separado con status la ejecución y el reenvío, y después recupera con start. No tomes BUILD SUCCEEDED por READY. |
| Conflicto de puerto | Si ya hay un reenvío del dispositivo correcto o un programa ajeno | Un reenvío correcto se puede reutilizar; si no, configura un puerto local libre. No mates procesos de pertenencia desconocida. |
| HTTP status alcanzable, fallan la sesión o source | El dispositivo del servicio, la session de PUA, la pantalla bloqueada del dispositivo / el proceso de prueba | Lee primero el error y el estado; si hace falta, reconstruye la sesión / reinicia el Runner. Vuelve a comprobar un viewport válido y la observación actual. |
| stale element reference con local.pid.0 / pua_foreground_unavailable | Si PUA / XCTest pueden resolver el primer plano real; no mires solo status.ready | Llama a pua_ready. Relee una sola vez la sesión / la interfaz; si el fallo continúa, sigue según recovery la recuperación en segundo plano del servicio cuya pertenencia ya se verificó. La observación y los ID de elemento antiguos quedan invalidados. |
| XCTDaemonErrorDomain Code=41 / Not authorized for performing UI testing actions | El estado de autorización del proceso de prueba y los ajustes de desarrollador del teléfono | Llama a pua_ready y sigue la recuperación. Si sigue fallando, el usuario revisa el desbloqueo, el modo de desarrollador / «启用 UI 自动化» y el aviso de confianza. No reintentes teclas en serie. |
| ready=false, state=recovering | El status de setup y el registro que corresponden a recovery.job_id | Es un estado normal de no estar listo; no lo tomes por READY porque isError=false. Sondea el mismo trabajo hasta recovery_phase=serving y vuelve a comprobar READY. El Runner es un servicio de larga duración y puede seguir en running. No repitas start ni esperes succeeded. |
| ready=false, state=recovery_required, reason=recovery_disabled | Si la llamada actual puso recover=false y si el usuario prohibió reiniciar / pidió un diagnóstico de solo lectura | Si la instrucción permite recuperar, llama a recover=true según recovery.next_tool / next_arguments. Si hay una restricción explícita, consérvala e informa del bloqueo del canal. El primer READY de una tarea normal usa el true por defecto; no desactives la recuperación por un prechequeo o por precaución. |
| pua_recovery_required, recovery.state=cooldown / manual | Tiempo de enfriamiento restante, configuración, pertenencia del worker y del puerto de escucha, y compilación válida | Durante el enfriamiento de 120 segundos, diagnostica según retry_after_seconds. Si la pertenencia no está clara o el servicio es externo, no mates procesos por el puerto; recupera según los pasos manuales devueltos. |
| HTTP timeout después de un toque, una escritura o un envío | La página / el campo / el mensaje reales en la observación que el paso siguiente necesita | Una escritura / un envío pueden haber surtido efecto. Mira primero el resultado real y continúa con lo que quede; no reejecutes solo. Una consulta pura puede releerse con un límite; no la trates como una mutación. |
| action_executed=true, action_complete=false | El estado real después de al menos una acción ya recibida | Aunque uncertain=false, relee primero. No reejecutes la escritura completa, el envío o el lote. Recuperar el canal solo recupera la capacidad de lectura / control; no sustituye la comprobación de negocio. |
| La app pide inicio de sesión, contraseña o biometría | El aviso de autenticación actual de la app de destino y su entrada normal | Pide al usuario que lo complete en persona según [toma de control por autenticación y recuperación](../../iphone-use/references/authentication.md). Durante la toma de control, pausa las llamadas al teléfono; cuando llegue el aviso de que terminó, vuelve a hacer observe, contrasta la app / la página de destino y continúa la tarea original. READY no representa que la app haya iniciado sesión, y la autenticación de la app no exige reiniciar PUA. |
| PUA responde, pero al árbol de elementos le falta contenido o falla la localización por etiqueta | Si la página está dibujada por la app, protegida, o si el árbol está truncado | No reintentes cambiando la etiqueta una y otra vez. Usa la captura adjunta al resultado fallido y toca por coordenadas. Para escribir, toca primero el campo y llama después a `pua_type_text` sin selector. Si aun así no se puede observar, informa de la limitación concreta. |

status devuelve un array `jobs`. Empareja el job_id pedido por id; no leas un job individual que no existe ni tragues una excepción de parseo. fetch / build se miran en su estado final de completado o fallido. Un start normal es un servicio de ejecución prolongada: con `service.ready=true` ya se puede llamar a READY, sin esperar a que el Runner pase a succeeded. Un trabajo de recuperación se vuelve a comprobar con READY cuando recovery_phase=serving. La consulta se basa en la fase actual, el registro y retry_after_seconds; no esperes en un intervalo largo fijo ni repitas start.

READY trae la observation actual; reutilízala directamente para preparar el paso siguiente. Un tap, Home, launch, una escritura y un desplazamiento habituales se ejecutan con optimismo por defecto. Un verified=false ordinario no obliga a detenerse ni a pedir otra observación. Cuando el paso siguiente necesita una página desconocida, esa misma acción devuelve la observación necesaria y se juzga el avance de paso. Solo el resultado final crítico usa expect / verify explícitos o una relectura del estado final. Unas coordenadas / region conocidas no exigen otra lectura de imagen o árbol para obtener un observation ID. Si usas un ID, tiene que venir del mismo Runtime y de una app / viewport coincidentes.

La ruta de PUA no depende de la ventana de duplicación del iPhone en el Mac, del origen de la pantalla ni de la exclusión mutua del bloqueo de la duplicación. Aun así, el bloqueo del dispositivo, la acción del usuario, una desconexión USB y la política de autenticación de la app sí cambian el estado de la prueba en el iPhone físico. Recupera solo según la evidencia actual del canal; no apliques el paso de «la duplicación tiene que bloquear el teléfono».

Material de firma: [Apple Personal Team](https://developer.apple.com/help/account/basics/about-your-developer-account), [aprovisionamiento de Appium](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/provisioning-profile/) y [firma automática de Appium](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/provisioning-profile/auto-config/). ## Conflicto de ocupación entre la duplicación y PUA

`mirroring_conflict`, un árbol vacío en la página de Ajustes o una captura de la pantalla bloqueada con «正在从 Mac 使用此 iPhone»: sal de la duplicación del iPhone en el Mac y, si hace falta, el usuario desbloquea el teléfono; vuelve a llamar a pua_ready. No sigas la tarea en un árbol vacío a base de repetir launch, tap o una escritura forzada. Que exista el proceso de duplicación no demuestra ocupación. La herramienta rechaza READY cuando el árbol está vacío y la duplicación está en marcha.
